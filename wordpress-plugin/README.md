# NivCreative – לוח ניהול לקוחות (תוסף וורדפרס)

לוח ניהול פרטי, בעברית וב-RTL, לניהול לקוחות, דפי נחיתה, תשלומים וחידושי שירות.
נגיש **למנהלי האתר בלבד** (`current_user_can('manage_options')`).

## התקנה
1. הורידו את `nivcreative-clients-dashboard.zip` (בתיקייה זו) או דחסו את התיקייה `nivcreative-clients-dashboard`.
2. בוורדפרס: **תוספים ← הוספה ← העלאת תוסף** ← בחרו את ה-zip ← **התקנה** ← **הפעלה**.
   (או העלו את התיקייה ל-`wp-content/plugins/` דרך מנהל הקבצים של Hostinger והפעילו.)
   בהפעלה נוצרות שלוש טבלאות: `wp_nivc_clients`, `wp_nivc_payments`, `wp_nivc_visits`.
3. צרו עמוד חדש (למשל "ניהול לקוחות") ב-Elementor.

## הוספה ב-Elementor
1. גררו ווידג'ט **Shortcode** לעמוד.
2. הדביקו: `[nivcreative_clients_dashboard]`
3. מומלץ: הגדירו את המכל/הסקשן ל-**Full Width** (או תבנית עמוד Elementor Canvas / Full Width) כדי שהטבלה תקבל מקסימום רוחב.
4. פרסמו. בכניסה כמנהל תראו את הלוח. מי שלא מחובר מועבר להתחברות וחוזר לעמוד אחרי הכניסה. משתמש מחובר שאינו מנהל רואה "אין גישה".

> לא מומלץ לקשר את העמוד מהתפריט הציבורי ולא לאפשר אינדוקס (התוסף שולח `noindex` בעצמו).

## אבטחה – מה נבדק בצד שרת
- כל נקודת קצה (`/wp-json/nivcreative/v1/...`) בודקת: משתמש מחובר ← `manage_options` ← (לפעולות כתיבה) nonce ייעודי `X-NIVC-Nonce` בנוסף ל-nonce הרגיל של REST.
- נתוני לקוחות לא מוטמעים במקור העמוד; הם נטענים רק אחרי אימות דרך ה-API, והתשובות נשלחות עם `Cache-Control: no-store`.
- נקודת הקצה היחידה הציבורית היא `/track` (ספירת צפיות בלבד, לא מחזירה מידע, ומתעלמת מנתיבים שאינם דפי לקוחות).
- הנתונים לא נמחקים בכיבוי, בעדכון או במחיקת התוסף (אין `uninstall.php` מכוון). למחיקה מוחלטת מחקו את שלוש הטבלאות ידנית.

## מטמון (Cache) – Hostinger
התוסף עצמו שולח `DONOTCACHEPAGE`, כותרות `no-store` ו-`X-LiteSpeed-Cache-Control: no-cache` לעמוד הלוח ולתשובות ה-API. בנוסף, כדאי להחריג במפורש:
- **LiteSpeed Cache (מותקן ב-Hostinger):** LiteSpeed Cache ← Cache ← **Excludes** ← *Do Not Cache URIs*: הוסיפו את כתובת העמוד (למשל `/clients-dashboard`) ואת `/wp-json/nivcreative`.
- **Hostinger Cache Manager / hPanel:** אחרי יצירת העמוד לחצו "Purge all" ובדקו שהעמוד לא מוגש למבקר לא מחובר (אמור להפנות להתחברות).
- **Cloudflare (אם קיים):** Cache Rule ← *Bypass cache* עבור הכתובת של העמוד ועבור `*/wp-json/nivcreative/*`.
- **WP Rocket / W3 Total Cache / אחרים:** הוסיפו את אותן כתובות לרשימת ה"Never cache URL(s)".

## נתוני צפיות (אנליטיקה)
בבדיקת האתר הנוכחי (`site/`) לא נמצא כלי אנליטיקה מחובר (אין Google Analytics / Site Kit / Jetpack), ולכן אין מקור נתונים קיים לקרוא ממנו. עד שיחובר מקור, העמודה והכרטיס מציגים **"לא מחובר"** ולא אפסים.

כדי לחבר: בלוח לחצו **"הגדרות נתוני צפיות" ← "הפעלת מעקב פנימי"**.
- המעקב סופר **צפיות** (כל טעינת דף) ו**מבקרים ייחודיים** (אנונימיים לפי יום; אדם שחוזר ביום אחר נספר שוב). אלה שני מדדים נפרדים.
- הנתונים נאספים **רק מרגע ההפעלה**. אין נתוני עבר.
- נמדדים רק דפי נחיתה שנמצאים באתר הזה (עמוד וורדפרס או כתובת מאותו דומיין). כתובות חיצוניות מוצגות כ"לא נמדד".
- המעקב פועל גם עם מטמון (הצפייה נשלחת בבקשה נפרדת). עמוד שנשמר במטמון לפני שהוגדר כדף של לקוח – נקו מטמון כדי שיתחיל להימדד.
- מנהלים מחוברים, בוטים ודפדפנים עם Do Not Track מוחרגים. אין עוגיות ואין שמירת IP (נשמר גיבוב יומי בלבד).
- אין אישורי אנליטיקה חיצוניים בתוסף, ולכן אין סודות לשמור. אם בעתיד תרצו Google Analytics 4 – יש להוסיף מחבר שירות עם אישורים בקובץ `wp-config.php` בצד השרת.

## הגדרות עסקיות
- **סכום ששולם** = סכום *כל* התשלומים שנרשמו ללקוח (תשלום ראשוני + כל החידושים). זה מה שמוצג בטבלה, בסינון, במיון ובכרטיס הסיכום. בטופס עריכה הסכום משנה רק את התשלום הראשוני.
- **תאריך יצירה** הוא תאריך דף הנחיתה (אפשר עבר). **"נוסף"** הוא מועד הוספת הרשומה לדשבורד, ונשמר בנפרד.
- **תפוגה** = שנה קלנדרית מתאריך היצירה (29.2 ← 28.2), לפי אזור הזמן של האתר (הגדרות ← כללי). יום התפוגה עצמו הוא היום האחרון הפעיל.
- סטטוס: **פעיל** (מעל 30 יום), **מסתיים בקרוב** (0–30 יום), **פג תוקף** (עם מספר ימי האיחור). זה משנה רק את התצוגה; דף הנחיתה לא נמחק או מושבת.
- **חידוש לשנה**: מאשרים תאריך התחלה וסכום; נרשם תשלום חידוש חדש והתפוגה החדשה היא שנה מתאריך ההתחלה. תשלומים קודמים נשמרים.
- מחיקת לקוח מוחקת רק את הרשומה וההיסטוריה שלה בדשבורד – לא את דף הנחיתה.
